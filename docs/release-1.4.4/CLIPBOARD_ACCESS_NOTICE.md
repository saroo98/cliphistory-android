# Clipboard access notice: local investigation

On 1 November 2026, a Pixel 8 Pro running Android 17 displayed “Shell pasted from your clipboard” during ClipHistory 1.4.1's connection test. Android's clipboard service logged the same message. A separate synthetic copy from another app produced the same notice while production recording was paused. The original eligible clipboard and production pause state were restored after both tests.

The notice is Android's clipboard-access warning. ClipHistory's Shizuku helper runs under the shell UID and must read clipboard contents to record copies made in other apps. Android shows a warning when that UID reads a clip owned by another UID. On the tested Pixel, “Show clipboard access” is a phone-wide setting. Turning it off also hides warnings for other applications. Android's separate copied-content preview is not controlled by this setting.

The local source adds an optional Settings → Privacy → Clipboard access notices explanation and a link to Android privacy settings on Android 12 and later. The app does not change the phone-wide setting. The link opened the Pixel's Android settings without changing the existing setting. Android 12 and 13 each passed 23 settings assertions, including the explanation and link; Android 11 passed 22, including absence of this control. The explanation was visually inspected on the Pixel in the isolated validation app.

The Pixel also ran a pre-shortcut 1.4.4 validation build: seven in-memory sensitive-policy assertions, 13 isolated encryption assertions with StrongBox, and 20 live assertions covering helper startup, marked-sensitive capture, interleaved deduplication and one-minute expiry from both encrypted copies. The eligible original clipboard was restored in the foreground and the production history count and pause setting were unchanged. These checks did not install the production candidate, prove every UI or device, or test HyperOS 3. Temporary validation Shizuku authorization was revoked after testing.

After the owner chose the optional shortcut, a separate local preview was built as `1.4.4-preview`, version code 13, so the intended code 14 release can replace it. An isolated source copy matched all 101 application source files in the candidate; only the preview version fields differed. Its signed APK uses the existing app certificate and has SHA-256 `7cd8c2f9a77679580dc9167fc739b71803b7077c1e8c8d0a774566338e174833`. This preview is not the F-Droid reference APK.

On an owned Android 14 emulator, in-place synthetic upgrades from 1.4.1 to both 1.4.4 and the preview preserved the app UID, wrapped key, authenticated snapshots, settings and the staged timed and indefinite sensitive entries. Each upgrade passed 16 stored-history assertions. The signed preview also displayed the warning explanation and opened Android privacy settings on that emulator.

The signed preview was installed in place on the Pixel. The installed APK hash and app UID matched expectations; the observed history count, limit, known settings and encryption status matched the pre-upgrade observation. The real connection test passed with ordinary recording paused, and the eligible original clipboard and pause state were restored. The installed shortcut displayed its explanation, opened Android privacy settings and supported Cancel. The phone-wide clipboard setting was unchanged. A matching history count is not a byte-for-byte comparison of personal entries.

The 1.4.4 candidate APK and recorded build hashes in [RELEASE.md](RELEASE.md) predate this UI change. A release build must be verified from its actual release commit. The notice remains visible while Android's setting is on; this change is a user-controlled workaround, not an app-only suppression of the warning. The owner accepted this limitation for publication. HyperOS 3 is still untested.
